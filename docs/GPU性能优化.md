# GPU与CPU开销优化

2026-10-21。保留战斗时序、输入和模型形状，优先减少CPU重复工作，并将粒子轨迹计算交给GPU。

- WebGL上下文设置 `powerPreference: high-performance`，请求高性能GPU；实际设备选择仍由浏览器/系统决定。角色的顶点蒙皮和表情形变继续使用Three.js已有GPU路径，骨骼姿势、输入、AI和伤害仍在CPU执行，不增加GPU读回和输入延迟。
- 金盾汇入粒子、吸收光雨使用顶点着色器计算轨迹。光雨每帧仅更新手部位置、角色位置和进度几个uniform，不再循环48个点并上传位置；金盾只在生成时上传32个起点，后续仅更新进度和目标。
- 命中粒子合并为一个固定192点的缓冲池，GPU按初速度和时间计算飞散、重力和淡出。重叠命中共用一次粒子绘制；只在命中生成时更新属性，不再逐个创建Mesh/Material、每帧更新或反复销毁。
- 跳跃、跳砸保留精确离地计算；每个骨骼矩阵每次探测只算一次，直接计算所需的高度分量，避免每个顶点反复乘骨骼矩阵。骨骼矩阵使用双精度缓存；活跃表情形变保留原通用精确路径。跳跃战斗判定复用已校正的高度，避免同帧重复扫描模型。
- 吸收举手只更新右臂相关矩阵，复用四元数/向量和姿势缓存，避免多次遍历整个骨架；闲置时跳过材质恢复和手部特效计算。界面数值、进度条和文字仅在实际变化时写入DOM。

## CPU对比

使用真实GLB、实际主循环和输入脚本；DOM/WebGL输出为替身，不包含浏览器布局、GPU绘制或驱动消耗，因此下面不是FPS、系统CPU占用率或端到端性能承诺。相同场景预热后重复5次，取整批中位耗时。待机900帧；跳跃12次、每次90帧；跳砸8次、每次20帧起跳后攻击并运行180帧；吸收10次、每次90帧。

| 场景整批 | 优化前 | 优化后 | 降幅 |
| --- | ---: | ---: | ---: |
| 待机 | 21.44 ms | 18.73 ms | 12.7% |
| 跳跃 | 1004.26 ms | 91.25 ms | 90.9% |
| 跳砸 | 998.57 ms | 149.59 ms | 85.0% |
| 金光吸收 | 65.67 ms | 37.83 ms | 42.4% |

原始结果在 `output/animations/runtime-cpu-before.json` 和 `runtime-cpu-after.json`；脚本为 `tools/benchmark_runtime.mjs`。CPU/GPU比例取决于设备和浏览器，没有人为增加无用GPU负载。

## 验证

`verify_gpu_runtime.mjs` 对27个动作共189个姿势，并施加世界平移和旋转，将优化后的探测与逐顶点实际蒙皮结果比较，最大误差约5e-16米；检查光雨和金盾缓冲不逐帧上传、命中粒子使用单个持续绘制对象。报告为 `gpu-runtime-verification.json`。

`compile_gpu_shaders.py` 用不显示窗口的本机OpenGL上下文，对Three.js实际点着色器展开后的光雨、金盾汇入、命中粒子，以及怒气纯红眼覆盖着色器进行编译、链接；四组通过。原生桌面GLSL测试不代替浏览器WebGL完整画面检查。源码及结果为 `gpu-particle-shaders.json`、`rage-eye-shaders.json`、`gpu-shader-compilation.json`。

30/60/144 FPS的跳跃高度、跳攻、金光吸收/回血、攻击与闪避打断、格挡、冲击晕眩和移动衔接回归通过；生产构建通过。未修改Blender/GLB源模型，也未使用持续GPU读回或改变战斗判定频率。
